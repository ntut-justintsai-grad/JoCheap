# v0.4 自由混搭主餐

主餐從單選套餐情境改為五種獨立選擇：披薩、炸雞、漢堡、紙包雞、義大利麵。可選一種或多種，預設仍為披薩與炸雞；不能取消最後一種。每種都會在需求摘要與結果覆蓋明細中呈現。

## 份量規則

依畫面順序將人數平均分配，餘數由前往後分配。每種至少分配一人；種類超過人數時提示可能過量。炸雞依食量抓一／二／三塊，一般漢堡、紙包雞與麵每人一份。披薩依尺寸、切法和食量換算整個披薩。這些都是可修改的配餐假設。

- 六人紙包雞＋義大利麵：各三份；預設六杯小飲料、至少六小份點心。
- 六人披薩＋紙包雞＋義大利麵：一個小披薩、紙包雞兩份、麵兩份。預設兩種披薩口味可能需要多買披薩，摘要會提醒。
- 七人漢堡＋紙包雞＋義大利麵：三個一般漢堡、兩份紙包雞、兩份麵。

新增可展開的「調整主餐份量」，只列已選主餐的最低件數。原有所有餐點明細仍可修改。若手動把某個已選主餐改成零，搜尋會要求恢復至少一份，或在主餐卡取消該種類。更換主餐種類會重新安排整餐建議份量。

主餐份數是最低需求，不排除優惠附送其他主餐。接受多出餐點並比較完整總額，附送餐點另列。選定品牌無法提供所需主餐時，會顯示無法湊齊，不偷偷省略該主餐。

漢堡另以一般漢堡的明確主餐分類計算；紙包雞與麵不能抵漢堡，小漢堡也不能充當一般漢堡主餐。此分類為引擎需求，購買清單仍列實際餐點。

## 文字與保留資料

中文文字可辨識任意多種主餐，支援「紙包雞3份、3份義大利麵」等數量前置或後置句型。摘要核對後才套用。海鮮／肉類偏好在同時選披薩與麵時分別套用；口味數限披薩。文字排除主餐會提醒仍可能有優惠附送，不宣稱完全排除。

本機設定使用 v4 格式，首次沒有 v4 時讀取 v3；舊披薩＋炸雞轉為兩個勾選，舊一般漢堡主餐數量轉成正確分類。

## 驗證

Node 28 組與 Python 8 組，共 36 組測試通過。新增測試覆蓋所有 31 種非空主餐組合，在 1／5／6／8 人時均保留每類最低份量；混搭解必須同時提供一般漢堡、紙包雞與麵，移除任一可供應優惠即不可冒充完整方案。既有獨立枚舉最低總額驗算仍通過。

來源快照的六人紙包雞＋麵，以及漢堡＋紙包雞＋麵可完成有限範圍搜尋。加入披薩口味等條件的複雜混搭仍可能達到 1.8 秒上限；會顯示搜尋未完成及目前找到的方案，不能宣稱已證明最低。未更動優惠事實或來源資料。

目前環境的瀏覽器控制與預覽面板無法啟動，未完成實際畫面、鍵盤、手機、剪貼簿及持久化操作測試。單檔建置已檢查腳本語法、JSON、唯一 DOM id、網頁操作所用 id 及無遠端執行依賴；這些檢查不能取代瀏覽器實測。
