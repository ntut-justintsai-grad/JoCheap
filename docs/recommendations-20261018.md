# 2026-10-18 混搭搜尋與接近方案修正

- 每次查詢依需求、日期、取餐、會員、付款與品牌限制重新建立候選券，不讀取預先配好的餐單。每張券維持單一來源版本及對應價格。
- 限時搜尋前，按各指定品項從候選券產生多個起點並補足缺額，讓紙包雞等餐點在大型券庫中也先有完整可行解。搜尋未完時保留目前解並明示限制，不宣稱全域最低。
- 在找到最便宜單品牌方案後，仍保留兩家混搭的搜尋分支及代表解；結果卡標示品牌組成。跨品牌不允許時維持限制。
- 從替代券搜尋發現的較低價格會更新比較排序及原需求預算參考，結果依實際金額排序。
- 已有完整方案時，不再以換掉餐點或增加份量湊推薦數量。
- 預設接近方案只會逐一放寬口味或飲料偏好、或保留每種原餐點至少 75% 的數量，不刪除任一指定餐點、不擅自跨越品牌、付款、會員或訂單上限。
- 無預算內完整方案時，同時呈現原餐點的超預算參考與實際缺額；更換餐點需另行選擇，下午茶不再自動變成披薩正餐。
- 個人餐不再強制至少一類點心或每人一份點心；不要求點心時，紙包雞、漢堡、義大利麵的需求只有使用者所選項目。

驗證：71 項 Node 測試、47 項 Python 測試；涵蓋獨立小型枚舉最低價、單品牌與混搭保留、替代食物需明示開啟、原餐點數量下限，以及實際券庫紙包雞限時搜尋。移除券庫中的紙包雞候選後不再得到紙包雞計價方案，證明結果依當次候選券產生。正式站實測另發現自然語言從下午茶切換到正餐會保留先前點心勾選；現已在情境切換時清除，明說「不要點心」也會清除原有點心。

## 完整需求報價固定保留

- 預算內無完整方案時，固定在結果最上方顯示「照原需求湊齊」的總額、原預算及差額，不再因超出 20% 而排在減份方案之後。
- 若主搜尋未取得完整報價或尚未完成，另以原餐點、份量、口味、品牌及資格條件執行獨立搜尋，只移除預算限制。若找到原預算內的完整方案，直接恢復為符合需求的推薦。
- 報價搜尋優先改善完整餐點總價，不耗時補找單品牌、混搭等不同代表解；仍未搜尋完成時，明示報價尚未證明最低。
- 若原訂單上限阻礙湊齊，另提供需要更多購買筆數的完整報價，列出新舊筆數；必須由使用者點擊採用才更改表單。會員、限購、付款、取餐、品牌等條件維持不變。
- 如果沒有符合條件的可計價品項、限購或口味無法滿足，或搜尋仍未完成，明確說明無法報出總價的原因。外送費未知時只列餐點小計，不把未知費用當作零元。

新增七項回歸測試涵蓋大幅超預算、獨立報價搜尋、原預算內方案恢復、需增加購買筆數、缺少品項、優惠資格與限購，以及未知外送費。

## 外送缺券與外帶替代通路

7 人、官方外送、預算 1,260、12 筆上限，需求小披薩 2 個、炸雞 4 塊、紙包雞 2 份及分享點心 6 小份的截圖可重現：本次券庫中紙包雞券的可用通路只標為外帶，因此外送候選沒有紙包雞。這是目前券庫的通路資料，不代表官方外送菜單沒有紙包雞，也沒有涵蓋所有正價單點外送價格。

- 額外檢查同品項在外帶是否有合資格候選，顯示「有外帶優惠，但沒有可計價的官方外送優惠」，不再只顯示籠統缺品項。
- 保留原餐點、份量、品牌、資格及訂單上限，另算明確標示為外帶的完整參考報價；不把它當作外送總價。
- 使用者點擊「改用外帶並重新試算」才切換取餐方式，原外送選擇不會被默改。
- 新增截圖情境、通路分離，以及會員、排除食物與品牌限制三項回歸測試。
