# v0.3 操作流程重整

使用者反映：欄位太多、操作不直覺，希望以程度選擇點心，依品牌分類，增加披薩份量／口味說明、文字需求框，以及義大利麵、紙包雞。

## 完成的改動

1. 首頁收斂為人數、預算、主餐、點心豐富度四組決策。自由文字是可展開的快速入口；其他條件移至進一步調整。
2. 點心依 1／2／3 類區分豐富度，份量由人數估算，套餐附帶點心一起抵需求。同類 QQ 球不灌水計種類。
3. 指定點心以品牌分組。結果列出真正拿到的點心類別，額外餐點扣除已滿足的主餐與分享需求。
4. 披薩尺寸分開估算片數；提供可以調整的切法與食量參考，不把片數當成普遍飽足承諾。
5. 可指定至少幾種口味與海鮮／肉類偏好。口味配置遵守來源中各區的名單；只重複同一口味不能滿足兩種需求。來源 6 選 2 保守視為兩款不同口味。
6. 加入紙包雞與義大利麵的獨立品項、已知來源紀錄及真正的主餐數量，不當作炸雞或漢堡的替代名稱。
7. 文字框先整理摘要再套用；辨識中文人數／預算、主餐、點心程度、披薩尺寸與口味數、通路，以及部分指定餐點數量。忌口、過敏、純素、精確數量限制會提示未能驗證。

## 新增來源證據

- 肯德基 `16298`：香草紙包雞、原塊炸雞與小飲料；`16461`：紙包雞、鱈魚圈圈與中飲料。維持各自規格，不拿中杯當成小杯。
- 必勝客 `16400`：筆管麵與小雞軟骨；`16358`：六選一私廚筆管麵與小披薩；`16118`：兩個大披薩。
- `16325` 在同一來源另有 189 元飯麵內容，與舊版收錄的 139 元披薩內容衝突。兩筆均隔離，未選較便宜者。
- 來源網址：https://info.talk.tw/kfc-coupon/ 及 https://info.talk.tw/pizzahut-coupon/ 。未達官方逐券核對。

## 實際驗證

Node 測試 24 組、Python 測試 8 組通過。既有 100 組小型資料與獨立枚舉的最低總額對照仍通過。

同一開發環境的六人情境：混合餐約 77 ms；披薩約 105 ms；漢堡約 6 ms；紙包雞約 183 ms。義大利麵加獨立小飲料的較複雜查詢，修正無法單品牌滿足時的不必要探索後，約 832 ms 搜尋完成。這些是開發環境的計算紀錄，不是手機或人工操作數據。

瀏覽器控制技能在本環境不可用，未啟動替代瀏覽器或假造截圖。尚未實測 375／768／1440 寬度、鍵盤與剪貼簿，也未招募三人完成可用性任務。

## 限制

- 文字理解目前是明確規則，不是通用 LLM；不懂的描述不能假裝已完全理解。只能套用摘要中列出的條件。
- 豐富度小份換算、披薩切片與食量都是公開可改的產品假設，不是營養等量。
- 本文件記錄 v0.3 當時限制。v0.4 已新增任意多種主餐的自由份量混搭，見 `mixed_mains_v04.md`；仍不處理半半披薩、完整過敏原或飲食排除。
- 點心品項按品牌分組；口味「海鮮／肉類」只為餐點偏好分類，不代表所有配料。
- 搜尋不包含同單併購、私人券與未展開的起價活動。來源更新與 GitHub 排程仍待實際驗證。
