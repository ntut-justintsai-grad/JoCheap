# 揪省：肯德基與必勝客聚餐試算

肯德基只採用官方點餐 API 衍生的 KCouper 公開快照，已移除好康情報誌與 Calling Taiwan 的肯德基記載。本站讀取快照，並非直接逐券呼叫官方 API。必勝客保留好康情報誌與 Calling Taiwan 的內容、價格及條件，並在每週更新時將每個唯一券碼配對至官方 `get_dgtAll` 查碼回傳的商品 ID。查碼成功不代表餐點與價目已完成官方核對。

預設納入啟用來源的完整餐點與定價配置，提供多種推薦、接近需求及超預算替代方案。每個來源版本獨立計算，保留原文、讀取時間與條件；同碼不同價格或餐點不會拼成一張不存在的券。

所有優惠碼均保留搜尋。必勝客官方查碼不接受的碼停止參與所有計價與替代方案；查詢錯誤保留上次成功紀錄與原時間，沒有成功配對時顯示待確認並停止計價。官方查碼對應的商品 ID、查碼時間及官方套餐連結會顯示於券卡、配餐與複製清單。缺價、餐點或選項無法完整辨識的版本仍顯示原文，待補足資料後才能計價，不以零元或猜測份量代替。

## 使用

設定人數、預算與主餐，再調整點心、飲料與下單條件。預設「所有來源版本」包含來源有差異的版本，結果會明示差異；也可選擇排除差異或只用仍適用的官方核對配置。官方核對是額外證據標示，不是預設推薦門檻。

餐點、價格、加價與效期來自同一版本。已知會員、付款、通路、時段及限購條件持續生效。未知下單條件可估算但會標示待確認；未知購買上限以使用者設定的最多訂單數作試算假設，不宣稱官方允許不限次購買。紙包雞與炸雞分開計數，替換時扣除原品並加上實際差額。

## 更新與部署

GitHub Actions 每週日 **08:17（Asia/Taipei）**重新擷取並解析三個啟用來源、逐碼配對必勝客官方查碼結果，再測試、稽核、建置與部署 GitHub Pages；排程可能延遲。手動執行可立即更新。推送程式碼會重新建置，資料未滿七天時沿用現有解析快照；解析器版本變更會重新解析。

來源失敗或筆數下降超過一半時保留該來源前次紀錄與原時間，顯示錯誤。本站讀取時間與上游更新時間分開記錄，不冒充逐券重新核對。官方額外核對失效不會把第三方來源估算偽裝成已核對。

Pages 使用 GitHub Actions，工作流程需要 contents:write、pages:write、id-token:write。

## 開發

Node.js 22、Python 3.12；無第三方套件依賴。

```sh
npm test
python -m unittest discover -s tests -p 'test_*.py' -v
python tools/crawl_catalog.py
node tools/check_trust.cjs
npm run build
npm start
```

測試涵蓋獨立枚舉計價、來源版本互斥、限制、替代方案及官方證據失效。測試通過不等於逐券內容已獲官方確認。`data/demo.json`、`tests/fixtures/` 為驗算資料，不可兌換。
