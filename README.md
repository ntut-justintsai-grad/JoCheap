# 揪省：優惠搜尋與有查核依據的配餐

肯德基與必勝客聚餐工具。優惠搜尋保留第三方來源；正式配餐及所有替代方案，只使用有官方核對證據、仍在適用日期與餐期內的基本配置。查核不是門市庫存或結帳接受保證。

目前核對的基本券為 KFC 50512、50514、50516、50529、50551。只適用官方當次查詢的日期、餐期與官網外帶，未開放第三方替換或升級。必勝客與紙包雞目前沒有通過同等範圍核對的配置，保留搜尋與原文，不提供其券價推薦。

## 使用

1. 設定人數、預算與主餐，可複選；混搭會依人數分配，每種主餐仍是必要需求。
2. 選點心豐富度，有需要再調整份量、飲料與點餐條件。
3. 比較已核對配置；每筆清楚列出餐點、券碼、基本價及加價，並可開啟官方券面、核對時間與證據。
4. 若無完整組合，顯示調整內容明確的替代／接近／超預算配置，或提供未計價的需求清單，不使用未核對券硬湊價格。

每碼本次最多一次，為本站保守限制，不是官方每日限購聲明。一張券獨立計作一筆訂單，門市是否接受分筆購買仍需確認。外送額外費用未知時不當零元；目前核對範圍只有官網外帶。

文字需求先解析成可檢查的欄位，再由使用者套用。份量及披薩切法是規劃假設，不是吃飽保證；口味標籤不能判定過敏原。

## 更新與部署

GitHub Actions 工作流程 `.github/workflows/pages.yml` 於 main 推送、手動執行及每六小時排程時更新。流程先測試，擷取第三方來源，再核對官方餐期、清單、已核對券面及使用條件，驗證正式資料，建置單一 HTML 並部署 GitHub Pages。

第三方來源失敗或筆數異常下降時保留其前次紀錄與時間。官方查核失敗、券面／價目／內容／使用條件異動、人工複查期限到期或來源內容異動時，停止推薦。排程不自動核准新配置，也不延長人工複查期限。瀏覽器會另行檢查已發布快照是否過期。

Pages 的部署來源應設定為 **GitHub Actions**；工作流程需要 contents:write、pages:write、id-token:write。GitHub 排程可能延遲，過期資料不因此繼續參與計算。

## 開發與驗證

Node.js 22、Python 3.12；無第三方套件依賴。

```sh
npm test
python -m unittest discover -s tests -p 'test_*.py' -v
python tools/crawl_catalog.py
node tools/check_trust.cjs
npm run build
npm start
```

`npm test` 包含獨立枚舉計價、需求／替代、跨語言查核綁定及建置測試。Python 測試包含解析、來源保留、官方異動、失敗及複查期限。`check_trust.cjs` 額外檢查剛更新的正式資料。

測試驗證規則，不代替逐券事實核對。`data/demo.json` 與 `tests/fixtures/` 是驗算資料，不能拿來兌換；`official_verified_20261017.json` 使用模擬圖片供失效測試，不是正式查核證據。

歷史版本研究保留在 `docs/`，舊的估算推薦行為已由目前的嚴格推薦資格取代。
